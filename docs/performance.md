# 性能规范

适用于 Codex、Grok、Claude、DSH 和后续新增实现。性能是验收条件，不能仅以功能测试通过代替。

## 日常刷新

- 以 FSEvents 驱动，保留现有 120ms 合并与 60 秒兜底扫描；不新增高频轮询。
- 组合监控只调用变更路径所属的源。未命中的源直接复用摘要，包括空结果；不得启动 CLI、解压或重新枚举。
- 未变化日志复用缓存，内容解析字节数为零。原生追加日志从上次完整记录继续读取；截断、替换或断点校验失败才重建状态。
- 活宿主核验与后台工作状态单独更新，不能为节省扫描而把静默运行误判为完成。
- 不在主线程做文件扫描、解压、CLI 查询或等待子进程。外部进程必须有超时；同时排空输出，避免管道填满后互相等待。

## 资源边界

- 限制历史扫描数量，保留活会话；子会话不能消耗主会话的名额。
- 不递归读取附件、模型缓存和工作目录。大日志流式读取，只解析影响摘要的事件，不反复解码图片、工具输出和请求上下文。
- 缓存只保留摘要与必要归并状态；文件删除、替换后及时失效。
- DSH 单次读取使用 64KiB 块，单行上限 16MiB、单次解码上限 128MiB，解压进程最多运行 10 秒。超限或损坏日志跳过并记录原因，不沿用旧完成状态。

## 验证

```bash
swift test -Xswiftc -strict-concurrency=complete -Xswiftc -warn-concurrency -Xswiftc -warnings-as-errors
swiftc -O -parse-as-library Sources/AgentInboxCore/*.swift scripts/benchmark_sessions.swift -o /tmp/benchmark-sessions
/usr/bin/time -l /tmp/benchmark-sessions
```

基准只读本机数据，输出各源冷扫、未变化文件事件中位数/P95、缓存全扫、组合层无关事件耗时和进程内存峰值；不输出对话或会话标识。未变化文件事件不能冒充真实追加性能。

性能回归测试以可验证的工作量为准：DSH 在超过 400KiB 历史后追加一个结束事件，解码量必须小于 512 字节；缓存扫描必须为零。压缩帧追加也必须少于首次完整解码。墙钟时间和 RSS 同时记录数据规模及环境，不用一次小样本声称绝对性能保证。

扫描执行期间继续到达的路径统一合并到下一批，同一时刻只允许一轮源扫描在途；同一轮内各源并行。损坏或超限文件在属性未改变前不重复解析，旧摘要不展示；保留有效断点供后续修复或完整追加时恢复。

Claude live CLI 查询最多 3 秒、输出最多 1MiB，失效后使用 transcript 状态；空会话目录不启动 CLI。

## 本机实测（2026-10-18）

环境：macOS 27.0.1、arm64、Swift 6.4，`swiftc -O`；只读本机现有数据。冷扫表示监控器缓存为空，系统文件缓存未清空。事件样本各 20 次；会话数为返回的主会话摘要数，并非日志文件总数。

| 来源 | 主会话数 | 首次扫描 | 未变化事件中位数 / P95 | 缓存全扫 |
| --- | ---: | ---: | ---: | ---: |
| Codex | 66 | 1224.92ms | 0.37 / 0.39ms | 17.35ms |
| Grok | 80 | 1617.23ms | 0.67 / 0.76ms | 144.87ms |
| Claude | 80 | 838.64ms | 0.27 / 0.31ms | 4.50ms |
| DSH | 80 | 2187.84ms | 1.49 / 1.59ms | 14.94ms |

DSH 缓存全扫实际解码 **0 字节**。组合层无关事件中位数 **0.087ms**、P95 **0.124ms**，未调用各源扫描。整个基准进程耗时 6.59 秒，最大 RSS 326.94MiB；该峰值覆盖四个来源的首次扫描，不代表常驻 GUI 或 DSH 单源内存。

真实追加成本另由回归测试验证：超过 400KiB 历史后补齐一个结束事件，解析量小于 512 字节；压缩日志追加只解码新增帧。119 项测试（109 项 Swift Testing、10 项 XCTest）与严格并发 Release 构建通过，包括 CLI 大输出、忽略 SIGTERM 时超时回退、20 个并发刷新及路径隔离。

这些数值是当前数据集的基线，后续修改应使用相同数据量与构建模式比较；不能据此推断任意数据规模或硬件的固定耗时。
